MANUAL DE CONTEXTO DEL PROYECTO Plataforma Integral de Gestión – Juegos
Evita Formosa

1.  JUSTIFICACIÓN DEL PROYECTO

La Secretaría de Deportes de Formosa administra actualmente los Juegos
Evita mediante planillas, documentación en papel y archivos dispersos.
Este proceso genera demoras, duplicidad de información, errores de
carga, dificultades para obtener estadísticas y una elevada carga
administrativa.

El objetivo del proyecto es construir una plataforma web integral que
digitalice el ciclo completo de los Juegos Evita, desde la inscripción
de participantes hasta la generación de reportes finales, centralizando
toda la información en un único sistema seguro, escalable y preparado
para producción.

La aplicación debe considerarse un software institucional. Todas las
decisiones de desarrollo deben priorizar mantenibilidad, seguridad,
trazabilidad, accesibilidad y escalabilidad.

2.  OBJETIVOS

• Eliminar procesos manuales. • Centralizar toda la información. •
Facilitar la inscripción mediante códigos QR. • Gestionar más de 40
disciplinas deportivas. • Administrar las etapas Zonal, Departamental y
Provincial. • Automatizar rankings y clasificaciones. • Generar
estadísticas y reportes. • Publicar información oficial para toda la
comunidad.

3.  FUNCIONALIDADES PRINCIPALES

Módulo Público - Consulta de disciplinas. - Reglamentos. - Noticias. -
Calendario. - Sedes. - Rankings. - Resultados. - Preguntas frecuentes.

Módulo de Inscripción - Acceso mediante QR. - Formulario dinámico. -
Validación de DNI. - Documentación obligatoria. - Estado de
inscripción. - Confirmación de registro.

Módulo de Administración - Gestión de usuarios administrativos. -
Gestión de participantes. - Gestión de equipos. - Gestión de
disciplinas. - Gestión de categorías. - Gestión de competencias. -
Gestión de resultados. - Gestión documental. - Auditoría. -
Configuración del sistema.

Motor de Competencias - Deportes individuales y colectivos. - Resultados
por tiempo, puntos, goles, sets o posiciones. - Clasificación
automática. - Avance entre etapas. - Rankings automáticos.

Reportes - Exportación CSV y XLSX. - Estadísticas por localidad,
departamento, disciplina, categoría y sexo. - Participación. -
Medallero. - Clasificaciones.

Seguridad - Control de permisos por rol. - Auditoría completa. -
Registro de acciones. - Validaciones en frontend y backend. - Protección
OWASP.

4.  REGLAS GENERALES

-   No improvisar funcionalidades.
-   Toda funcionalidad debe respetar los requisitos del proyecto.
-   No duplicar lógica.
-   Mantener compatibilidad entre módulos.
-   Documentar cambios relevantes.
-   Mantener arquitectura limpia y modular.

5.  METODOLOGÍA

El desarrollo seguirá Scrum.

Sprint 0 - Ingeniería de requisitos. - Arquitectura. - Modelo de
datos. - Mockups. - Planificación.

Sprint 1 - Infraestructura. - Autenticación administrativa. -
Participantes. - Inscripciones.

Sprint 2 - Equipos. - Disciplinas. - Categorías. - Documentación.

Sprint 3 - Competencias. - Resultados. - Rankings. - Clasificaciones.

Sprint 4 - Reportes. - Noticias. - Calendario. - Estadísticas.

Sprint 5 - Optimización. - Testing. - Correcciones. - Despliegue.

Cada Sprint debe finalizar con funcionalidades completas, documentadas,
probadas e integradas.

6.  DIRECTRICES PARA LA IA

Antes de implementar cualquier cambio: 1. Analizar dependencias. 2.
Revisar módulos existentes. 3. Evitar romper funcionalidades. 4.
Mantener coherencia arquitectónica. 5. Respetar contratos entre frontend
y backend. 6. Priorizar código reutilizable. 7. Aplicar SOLID, DRY y
KISS. 8. Mantener el proyecto preparado para producción.
